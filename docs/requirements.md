# 正缘测试网站制作提示词

这份提示词用于制作「想知道你的正缘是什么样子吗」测试网站，覆盖视觉、首页、答题、结果、分享海报、管理后台与开发验收。可将全文直接复制给 AI 建站或编程工具；附录已包含原文完整题库和三类结果，不需要另外上传原文才能理解产品。

来源：用户提供的《正缘测试产品完整方案文档》。18 道题、六维度、三类结果、基础配分和隐藏彩蛋来自原文。页面尺寸、按钮状态、内容版本、权限细化和工程交付要求是本方案补充的实现建议。

计分解释：原文同时规定“并列时比较单维最高分”和“三类组合分完全相同时默认 A”。本方案建议将“三类完全同分”作为特殊分支，先于一般同分比较执行；两类并列时才比较单维最高分。这是为消除实现歧义而补充的推荐解释。

以下为可复制的完整建站提示词。

---

请以产品设计师和全栈工程师的标准，设计并实现一个中文、移动端优先的恋爱关系偏好测试网站。产品主题为「想知道你的正缘是什么样子吗？」。请按下列要求交付完整可运行项目，并使用附录中的真实题库与结果内容初始化系统。

**一 产品定位与建设范围**

产品通过 18 道生活场景单选题，帮助用户梳理理想长期伴侣的相处风格。目标用户是对恋爱话题、人格测试与社交分享感兴趣的年轻用户，单次体验约 3–5 分钟。

用户获得六维关系偏好、三类主结果之一，以及符合条件时出现的隐藏称号。全站文字温柔、清晰、有共鸣，避免夸大。结果是娱乐与自我探索参考，不宣称能够预测具体伴侣、婚期或真实恋爱结局，也不包装成心理诊断。

需要实现：首页、答题页、提交确认、结果页、分享海报页、管理员登录与后台、隐私说明与测试说明。普通用户无需注册或填写手机号即可完成测试。首版不设置付费解锁、强制分享、强制关注或广告拦截流程。

主流程：首页 → 开始测试 → 完成 18 题 → 确认提交 → 查看结果与雷达图 → 生成并保存海报。支持返回改答案、刷新恢复、重新测试和返回首页。

**二 整体视觉与配色**

视觉关键词：梦幻、浪漫、轻盈、温柔、留白、轻微神秘感。将网站设计成一封逐步展开的关系探索信笺，使用奶油白纸感背景、淡紫与柔粉渐变、少量星光与星轨装饰。首页和结果页可加入信封、月亮、花束和抽象人物剪影；装饰应衬托正文。

避免把视觉做成算命祭坛、暗黑占卜界面或满屏闪烁粒子。使用真实排版与可读的中文文字，不把正文烘焙进装饰图片。

配色系统：

| 用途 | 色值 | 使用要求 |
| --- | --- | --- |
| 品牌主色 | #A78BFA | 星轨、图表、选中态浅色背景和品牌识别 |
| 主按钮深紫 | #7C3AED 至 #6D28D9 | 主操作按钮，可搭配白字；保证文字对比度 |
| 柔粉辅助色 | #F4B8D0 | 渐变、花朵、局部装饰 |
| 浅蓝点缀色 | #B8DDF5 | 星光、辅助图形、小面积高光 |
| 页面底色 | #FFF9F5 | 主背景和内容留白 |
| 正文深色 | #30273E | 标题与正文 |
| 次级文字 | #6F667C | 提示、说明和辅助标签 |
| 卡片及边框 | #FFFFFF / #E8E0F2 | 选项、结果模块、表单与轻量分隔 |

字体使用系统中文无衬线字体，优先 PingFang SC、Microsoft YaHei。移动端正文 16px 左右、行高 1.6–1.8；首页主标题约 32–40px，可随屏幕调整。主文字不使用浅粉或浅紫。一般正文与背景对比度至少 4.5:1。

卡片圆角建议 20–24px，按钮圆角 14–18px，按钮高度至少 48px，点击区域至少 44×44px。采用轻阴影和细边框，减少厚重描边与过度磨砂。页面切换约 200–300ms；支持减少动态效果偏好。

移动端内容最大宽度约 480px，左右留白 20px；桌面首页可扩展为文字与插画双栏，答题区保持聚焦。适配 320–1440px 常见宽度、手机底部安全区和中文长文案。答题页以单题为单位，长题或大字体时允许自然滚动，不强行锁死一屏高度。

**三 首页要求**

首页首屏应能让用户理解“测什么、多久、能得到什么”，并看到开始按钮。

1. 顶部放置简洁品牌标识与「正缘画像」名称，提供低干扰的测试说明入口。
2. 主视觉使用一封被星轨环绕的信封或信笺，配少量柔和月亮与花朵。
3. 主标题：「想知道你的正缘是什么样子吗？」
4. 副标题：「18 道题，看看什么样的人更适合与你长久相伴。」
5. 信息标签：「18 道情境题」「约 3–5 分钟」「六维关系画像」。
6. 主按钮：「开始寻找我的正缘」。下方简短说明「凭第一直觉选择，没有标准答案」。
7. 有未完成记录时，提供「继续上次测试」和次级操作「重新开始」；重新开始前说明将清除当前未完成进度。

首页引言使用以下原文，可按阅读节奏分为三段，保持首屏简洁：

每个人心里，都藏着一份关于爱情的想象。有人渴望被坚定选择，有人期待灵魂同频，也有人希望两个人能一起成长、一起看更大的世界。

所谓正缘，不一定是最耀眼、最完美的那个人，而是那个与你的节奏合拍、愿意理解彼此，也能让你自在做自己的人。

接下来，请凭第一直觉回答 18 道小问题。没有标准答案，也不用刻意选择“正确”的选项。完成后，你将获得一份专属于你的理想伴侣画像，看看什么样的人更可能与你长久相伴。

首屏以下展示“完成后你会获得”：理想伴侣画像、六维关系偏好、相处建议、专属分享卡。可展示三类结果的简洁示意卡，不伪造测试人数、用户评价或准确率。

页尾与主按钮附近用清晰可读的小字提示：「本测试仅供娱乐与自我探索参考，不代表对现实恋爱或未来关系的确定预测。」并提供隐私说明入口。

**四 答题页与提交要求**

顶部显示返回入口、当前位置「第 1 / 18 题」与答题进度。位置进度与“已完成 X / 18”应准确区分；不能只因进入第 1 题就统计已经完成 1 题。

每次展示一道题，固定 Q1–Q18 顺序，选项固定 A/B/C/D 顺序。每题恰好四个选项，单选。使用大面积可点击卡片，选中时同时出现加深边框、浅紫底和勾选图标，不能仅靠颜色表达状态。

默认点击选项后留在当前题，由用户点击「下一题」继续，便于确认和修改。未选答案时禁用下一题并提供简短提示。底部有「上一题」「下一题」，第 1 题不出现无效的上一题动作，第 18 题改为「查看我的结果」。

返回上一题应保留已选项。切题时保留所有答案；刷新或意外关闭后，可在同一设备恢复有效期内的未完成进度，恢复时提示「已恢复上次答题进度」。缓存至少包含测试版本、会话标识、当前题号与答案；版本失效时给出明确说明和重新开始入口。

主动退出未完成测试时提供继续答题和保留进度退出选项。切题后将键盘焦点移到题干，选项使用原生 radio 或具备等效无障碍行为的控件。

最后一题完成后，提供提交确认与「返回检查」。只有服务端确认 18 题全部有效后才生成正式结果。提交过程中按钮显示加载状态并防止连点；失败保留答案并支持重试；超时或重试不应产生多条完成记录。不要使用虚假的“正在扫描命运”或强制长时间等待动画。

**五 计分与判定规则**

基础配分保持为 A=0、B=1、C=2、D=3。选项字母在不同题目中不具有固定心理学含义。该配分是原方案的娱乐性规则，不能将得分解释为关系能力、人格优劣、科学诊断或人群排名。

| 代码 | 维度名称 | 题目 | 分数范围 |
| --- | --- | --- | --- |
| D1 | 情绪安全感 | Q1–Q3 | 0–9 |
| D2 | 沟通共鸣度 | Q4–Q6 | 0–9 |
| D3 | 价值观契合度 | Q7–Q9 | 0–9 |
| D4 | 共同成长力 | Q10–Q12 | 0–9 |
| D5 | 浪漫吸引力 | Q13–Q15 | 0–9 |
| D6 | 边界与自由度 | Q16–Q18 | 0–9 |

三类组合分：

- TYPE_A 稳稳相伴型 = D1 + D6。
- TYPE_B 灵魂共振型 = D2 + D5。
- TYPE_C 并肩成长型 = D3 + D4。

三类组合分范围均为 0–18。类型代码使用 TYPE_A/B/C，避免与选项 A/B/C/D 混淆。

先计算并保存全部维度、三类组合分和基础主结果，再确定展示称号。基础主结果按以下顺序判定：

1. 三类组合分完全相同：标记 balanced=true，基础主结果默认 TYPE_A，结果页增加「均衡型偏好」提示。此特殊规则优先于一般同分比较。
2. 存在唯一最高组合分：选择该类型。
3. 仅两类并列最高：分别取各自两个核心维度中的最大分，最大分更高者胜出。
4. 若仍然相同：按 TYPE_A > TYPE_B > TYPE_C 的优先级选择。

彩蛋规则：统计 18 道题中各选项字母出现的次数。同一字母出现 15 次及以上时，将展示称号覆盖为「宇宙限定款」，但基础主结果、balanced 标记、三类组合分和六维分数全部保留。彩蛋不额外加分。

彩蛋文案：「你有一种很稳定的恋爱直觉。比起追逐标准答案，你更相信自己真正舒服的相处方式。」

使用 base_result_code、display_result_code、is_easter_egg、balanced 等独立字段，避免隐藏称号覆盖后丢失主类型或造成重复统计。不得根据姓名、生日、星座或随机数生成结果。

**六 结果页要求**

结果页采用展开信笺式布局，按以下顺序展示：

1. 结果开场：「你的理想长期伴侣画像是」。
2. 主结果名称、主题插画与四个关键词。彩蛋命中时主标题优先显示「宇宙限定款」，基础类型以小标签展示。
3. 核心评语，使用附录原文。
4. 正缘画像，围绕性格倾向、沟通方式、相处节奏、关系需求分段呈现。可对原文做忠实结构化，不凭空增加职业、年龄、外貌或相遇时间等预测。
5. 六维雷达图及每项真实得分，固定量程 0–9，标签与附录维度一致。小屏避免标签重叠，可在图下提供文字分数列表。图形描述为「本次作答对应的关系偏好分布」，不把低分写成缺陷，也不把 9 分写成 90% 匹配率。
6. 相处建议：以原文建议为基础整理成 2–3 条可执行建议，保留原意，并与原文画像区分。
7. 总结金句：使用附录的结果总结，适合截图。
8. 操作区：「生成专属分享海报」「重新测试」「返回首页」。

三类插画保持统一画风：稳稳相伴型可用暖灯、月光与并坐剪影；灵魂共振型可用对话星轨、音符与信笺；并肩成长型可用双人旅行、并行道路与新芽。彩蛋可用星环徽章，但不显示“稀有率 1%”等没有依据的数据。

三类组合分全相同时展示：「你的本次作答在三类关系偏好上较为均衡，可以结合六维分布一起理解。」该提示可与彩蛋共存。

结果应保存为提交时的快照。刷新、关闭后重开有效链接、后台修改内容后再次访问历史结果，都应读取原版本结果，避免已经分享的结果改变。重新测试创建新会话，保留旧结果直到规定的保存期限届满。

**七 分享海报页要求**

生成 1080×1440px 竖版 PNG 海报，风格与结果页一致。包含测试主题、结果名称、关键词、总结金句、缩略雷达图、品牌标识、指向测试首页的真实二维码或短链接，以及简短的娱乐参考说明。

默认不展示姓名、手机号或原始答案。昵称为可选项，用户主动填写后才显示，并设置合理长度限制和安全的文本处理。二维码默认指向公开测试入口，分享海报不能泄露私有结果访问凭证。

页面提供海报预览、「保存图片」「复制分享文案」「返回结果」。分享文案按真实结果替换类型，例如：「我测出了自己的正缘画像：稳稳相伴型。你更适合什么样的人？来测测看。」

等待字体、插画、图表和二维码加载完成后导出，确保长名称不溢出、中文不缺字、图表不被截断、二维码可识别。移动浏览器无法直接下载时，展示可长按保存的图片与说明；不承诺网页能直接发布到朋友圈。

如浏览器支持系统分享，可在用户主动点击后调用原生分享。埋点记录“点击分享”“生成海报成功”等实际事件，不将其宣称为“已成功分享给好友”。

**八 管理后台要求**

后台使用清晰的白底和轻紫强调色，采用侧边导航、顶部操作区、可读表格和编辑表单。导航包含：数据概览、题库管理、结果管理、规则配置、页面与素材、账号权限、操作日志。

管理员通过真实身份认证登录，支持退出和会话过期处理。至少设三种角色：

- 超级管理员：账号与角色、规则、内容、发布、统计和导出管理。
- 内容编辑：维护题目、结果文案和素材，预览与保存草稿，默认不拥有账号、敏感规则或导出权限。
- 数据查看：查看聚合统计；默认不能修改内容，明细导出需单独授权。

权限在服务端与数据库层验证，不能仅通过隐藏菜单限制操作。

题库管理：列表展示题号、题干、维度、顺序、启用状态；支持搜索、编辑、排序、草稿新增与停用；编辑页包含题干、四个选项、选项分值、所属维度。首版发布必须严格满足 18 题、每题四选项、每维度三题、配分范围 0–3。新增或停用操作不得使线上活动绕过这些校验。

结果管理：维护三类结果与彩蛋称号，包括名称、关键词、评语、画像分析、建议、总结金句和封面插画。支持移动端预览，图片提供替代文字。默认导入附录全部结果原文。

规则配置：展示三类组合维度、同分优先级、完全同分默认类型、彩蛋开关与阈值。初始配置严格使用上文规则。限定每类组合包含两个维度、六个维度各使用一次，避免不同量程直接比较。修改评分配置先在草稿中试算，检查后由有权限角色发布新版本。

页面与素材：编辑首页标题、引言、按钮文案、隐私和测试说明、品牌标识、结果插画与海报样式。图片上传验证文件类型和大小；说明与富文本安全处理，避免直接执行上传内容。

版本发布：支持草稿 → 预览 → 校验 → 发布；保存修改不等于立即更新线上内容。版本保存题库、配分、规则、结果文案与关键素材快照，发布记录包含操作者与时间。已开始的答题会话绑定原版本；旧会话有效期内继续使用其原版本。历史结果引用原快照，不被新发布内容覆盖。回滚只改变新会话使用的版本。

数据看板至少显示：去重访问人数、开始人数、完成人数、开始率、完成率、平均答题耗时、基础类型分布、隐藏彩蛋触发比例、六维均值、海报生成与分享按钮点击指标。支持时间和测试版本筛选、加载状态、空数据状态及口径说明。

漏斗指标使用同一统计队列及去重口径：开始率 = 开始人数 / 首页访问人数，完成率 = 完成人数 / 开始人数。重复测试的会话次数另列，不与人数混用；零分母显示“暂无数据”。平均耗时使用明确的开始至完成口径。三类基础类型分布总和应为 100%；隐藏彩蛋作为独立触发比例展示，或另建互斥的展示结果分布，不重复相加。

CSV 导出提供时间、版本、字段选择与导出条数预览，默认导出聚合信息。原始明细须额外授权、最小化字段并记录操作日志；不能包含访问令牌或其他密钥。对用户可输入字段做 CSV 公式注入防护。

**九 数据 接口与技术实现**

推荐技术栈：React + TypeScript + Vite；Tailwind CSS 与 shadcn/ui 或自定义组件；Apache ECharts 雷达图；Supabase PostgreSQL、Auth、Storage 与服务端函数。可采用等效技术，但需交付真实持久化与可执行鉴权。

普通用户前台不要求登录界面；如使用 Supabase，可用匿名身份建立会话所有权。管理后台使用独立的角色授权。匿名身份也不得读取其他用户的记录。

路由建议：

- / 首页。
- /test 答题页，读取当前会话与版本。
- /result/:id 结果页，校验访问权限。
- /share/:id 海报页，校验访问权限。
- /privacy 隐私说明。
- /about 测试说明。
- /admin/login 管理员登录。
- /admin 后台首页及各模块子路由。

数据实体至少包含：

- test_versions：版本号、状态、发布时间、规则与内容快照。
- dimensions：维度代码、名称、说明。
